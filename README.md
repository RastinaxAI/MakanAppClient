## استقرار

[راهنمای کامل فارسی، پیش‌نیازها، انتقال نسخهٔ قبلی و پشتیبان‌گیری](DEPLOYMENT.fa.md) را بخوانید. پس از انتقال سورس به سرور، از ریشهٔ همین مخزن اجرا کنید:

```bash
sudo bash ./deploy.sh init && sudo bash ./deploy.sh check && sudo bash ./deploy.sh up
```

اجرای دوبارهٔ `init` فایل محیط موجود را حفظ می‌کند. پس از پیام موفقیت init به `check` و `up` ادامه دهید. بخش انتقال تنظیمات قدیمی فقط زمانی لازم است که فایل‌ها و داده‌های نصب production قبلی واقعاً موجود باشند؛ مسیرهای `/etc/makanapp/...` روی نصب تازه لازم نیستند.

اگر لندینگ production قبلی با داده‌های موجود دارید، ابتدا مراحل انتقال و واردکردن کلیدها و volumeهای قبلی در راهنما را انجام دهید.

HTTPS با ایمیل `rastinaxoffice@gmail.com` تنظیم شده است. فایل محیط واقعی، رمزها، نشست‌ها و پشتیبان‌ها محلی می‌مانند؛ فقط نمونه‌های بدون رمز در Git نگهداری می‌شوند.

## به‌روزرسانی نسخهٔ نصب‌شده

سورس جدید را مطابق بخش انتقال در راهنما همگام کنید؛ حذف فایل‌های قدیمی `src` دو کلاینت نیز باید منتقل شود. سپس روی سرور اجرا کنید:

```bash
cd /opt/makanapp
sudo bash ./deploy.sh up
```

این به‌روزرسانی به ساخت imageها از سورس جدید نیاز دارد؛ فرمان بالا ساخت، backup، migration، اجرا و بررسی HTTPS را انجام می‌دهد و کلیدها و داده‌های نصب قبلی را حفظ می‌کند.

## بررسی تنظیمات استقرار

```bash
python3 -m unittest discover -s deployment/tests -v
```

وضعیت build و محدودیت‌های اعتبارسنجی در بخش پایانی راهنمای استقرار ثبت شده‌اند.

دانلود وابستگی‌های Python لندینگ از mirror HTTPS و با همان نسخه‌ها و hashهای `uv.lock` انجام می‌شود. بسته‌های Debian در API و وب نیز از mirror HTTPS و با امضای رسمی Debian دریافت می‌شوند. بخش رفع خطای راهنمای استقرار، بستهٔ اصلاح دانلودها و فرمان ادامهٔ نصب را توضیح می‌دهد.

توقف نسخهٔ قبلی روی `Running migration` در ترمینال SSH نیز اصلاح شده است. migration و ورود محتوا اکنون بدون ورودی تعاملی و با timeout سازگار با ترمینال اجرا می‌شوند. بخش مربوط در راهنمای استقرار، ادامهٔ نصب با imageهای ساخته‌شده را توضیح می‌دهد.

## پاکسازی خروجی‌های اضافه

برای پیش‌نمایش اختیاری و سپس حذف خروجی‌های تولیدشدهٔ تست، بازبینی و پوشه‌های موقت مشخص:

```bash
bash ./deploy.sh clean --dry-run
bash ./deploy.sh clean
```

پاکسازی به Docker روشن نیاز ندارد. سورس، مراجع طراحی موردنیاز ابزارها، اسناد تحویلی PDF/Word، وابستگی‌ها، فایل‌های محیط، backupها، رسانه‌ها و sessionها حفظ می‌شوند. خروجی مربوط به پیش‌نمایش یا تست فعال و مسیرهای symlink نیز حفظ می‌شود. فرمان به volumeها یا سرویس‌های Docker دسترسی ندارد.

در بررسی محلی ۱۱ نوامبر، ۳۱٬۴۳۹ فایل تولیدشده با حجم حدود ۱٫۳ گیگابایت حذف شد. ورودی Docker کلاینت از ۶۷٫۹ به ۷٫۴ مگابایت و حجم هر image پنل حدود ۳۲ مگابایت کاهش یافت. زمان آماده‌شدن مجموعه در آزمون محلی از ۱۹٫۰۳ به ۱۲٫۸۶ ثانیه رسید؛ این اعداد مربوط به ساخت و شروع سرویس‌ها هستند.

پس از انتقال نسخهٔ جدید مطابق راهنما، روی سرور اجرا کنید:

```bash
cd /opt/makanapp
sudo bash ./deploy.sh clean && sudo bash ./deploy.sh up
```

این نسخه به Docker Engine 25+ و Compose 2.24+ نیاز دارد. دامنه‌ها و پورت‌های عمومی ۸۰ و ۴۴۳ همچنان از همان Caddy مشترک استفاده می‌کنند.
