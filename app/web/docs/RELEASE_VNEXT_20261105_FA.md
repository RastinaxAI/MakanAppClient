# اتصال انتشار vNext - ۵ نوامبر ۲۰۲۶

برنامهٔ فعال فقط `web/` است؛ حساب شخصی، دانشجو، معلم، والد و مدیر آموزشگاه. راهنمای۲۵صفحه‌ای vNext کامل خوانده شد؛ برچسب Target/Pending در سند با نبود قطعی API یکسان فرض نشد. OpenAPI همان محیط تست دوباره دریافت شد:۴۴۲عملیات در برابر۴۳۳عملیات قبلی،۹عملیات افزوده و بدون حذف.۸عملیات تازه عمومی‌اند و یک عملیات تازهٔ مالک از SDK و BFF کلاینت کنار گذاشته شد. سطح اجرایی کلاینت با GET تنظیم Web Push،۲۸۶عملیات و۵۰۶schema دارد. نام80c2e61 مبنای سند است، نه attestation باینری مستقر.

## معماری و رفتار خطا

هماهنگ‌کنندهٔ موجودِ قصد عملیات به `features/personal/use-resource-command.tsx` منتقل و نام قبلی `useClassCommand` به‌صورت alias حفظ شد؛ کلیدهای pending قبلی عوض نشدند. شناسه قبل از ارسال در sessionStorageِ محدود به کاربر/زمینه ذخیره و در خروج پاک می‌شود؛ توکن یا کلید نشست وارد مرورگر نمی‌شود. نتیجهٔ نامعتبر به منبع دیگر، موفقیت نمایش داده نمی‌شود. ۴۰۳/۴۰۹/۴۱۲ سبب بازخوانی دادهٔ همان زمینه می‌شوند، ولی دلیل و نوشتهٔ کاربر را پاک یا نسخهٔ تازه را خودکار تأیید نمی‌کنند.

نسخه‌ها opaque می‌مانند و بازکدگذاری یا مقایسهٔ عددی نمی‌شوند. هر aggregate نسخهٔ خودش را دارد؛ فرمت خاص نسخه به کل جریان‌های قدیمی تحمیل نشده است. خطا از code و correlation/trace metadata خوانده می‌شود؛ متن انسانی detail برای تصمیم برنامه parse نمی‌شود. تازه‌ترین Snapshot و capability سرور مرجع‌اند، نه عنوان نقش یا DOB.

متن‌های تازه در `src/content/fa.ts` زیر `vnext` و نشانی سرویس در `config/network.json` است. چیدمان/تم/فونت/ناوبری V3 و اجزای موجود حفظ شدند؛ قالب عمومی جایگزین نشده است. کلاس مستقل با Organization یا Enrollment ساختگی مدل نمی‌شود. فهرست دانش‌آموز/والد به DTO خصوصی ارزیاب یا answer key متصل نشده است.

## آزمون و شواهد

نتیجهٔ دقیق در [شواهد آزمون](quality/VNEXT_20261105_CHECKS.json) ثبت شده است:

- ۴۵۵ آزمون واحد در ۶۴ فایل موفق، شامل ۸ آزمون جدید قرارداد vNext.
- آخرین نتیجهٔ هر ۲۱۹ سناریوی مرورگر موفق، شامل ۱۰ سناریوی جدید. اجرای کامل، ۲۱۷ موفق و ۲ شکست داشت؛ بازاجرای تمام ۱۶ سناریوی دو فایل مرتبط و سپس آزمون تقویت‌شدهٔ مجوز موفق شد. صفر retry خودکار؛ این نتیجه به‌عنوان یک اجرای کاملِ بدون شکست معرفی نمی‌شود.
- build تولیدی standalone، typecheck، format، بررسی ۳۵۰ ماژول بدون چرخه و صحت SDK تولیدشده موفق‌اند.
- ۱۶ آزمون setup و ۹ آزمون runtime موفق‌اند؛ اجرای setup با Bubblewrap و Docker ساختگی انجام شد. اجرای اولیه با runner پیش‌فرض Docker به‌علت نبود image/daemon نتوانست setup را آغاز کند؛ گزارش آن حفظ شده است. این آزمون‌ها جای build یا اجرای کانتینر واقعی نیستند.
- ۷۵ بررسی HTTP صریح برای پنج نقش روی Test مطابق انتظار بود؛ زمینهٔ نشست‌ها حفظ و خروج نشست‌های خود ابزار تأیید شد.
- ۵۶ تصویر زنده و ۲۴ تصویر فرم‌های fixture در چهار عرض و دو تم تهیه شد. کنترل سرریز افقی، تطبیق تم واقعیِ نماهای زنده و بازبینی تصویری نمونه‌ها انجام شد؛ [گالری محلی](../output/review/vnext-20261105/index.html) شامل هر ۸۰ تصویر است.

شکست‌های میانی حذف نشده‌اند. بررسی عمومیِ byte در یک مرحله، نسخه‌های opaque جریان‌های ارزیابی قبلی را رد می‌کرد؛ این محدودیت برگشت داده شد و آزمون‌ها دوباره اجرا شدند. دو شکست اجرای کامل بعدی، قطع اتصال challenge ورود و انتظار قدیمی فرم grant برای گیرندهٔ Manager بودند. fixture دومی با تصمیم جدیدِ گیرندهٔ Teacher تطبیق داده شد؛ آزمون منفی همچنان رد Manager و اختیار خارج از محدوده را تأیید می‌کند. همچنین انتظارهای قدیمی تعداد تب گزارش و نبود فهرست ارسالی با قابلیت منتشرشدهٔ تازه اصلاح شدند.

آزمون‌های واحد تازه، سطح مجاز API، تقدم مسیر literal discovery، دو نسخهٔ مستقل، قصد ایجاد کلاس، تطبیق رسید عضویت، مسیرهای لغو مجاز، زیرمجموعهٔ اختیار آموزشی و gate پیش‌فاکتور را بررسی می‌کنند. آزمون‌های مرورگر تازه، صفحه‌بندی/لغو دعوت، حفاظت آخرین مدیر، حفظ نقش دیگر، تعارض نسخه، ACK گم‌شده با reload، کشف Draft، گزارش محتوا، نام والد، هویت امن دعوت و تم/اندازهٔ فرم‌ها را پوشش می‌دهند.

شواهد زنده در `quality/VNEXT_20261105_LIVE.json` و قرارداد در `quality/VNEXT_20261105_CONTRACT.json` هستند. ابزار `scripts/verify-vnext.mjs` خارج از CI و فقط با opt-in، روی Test مشخص و نشست مستقل اجرا می‌شود. تنها POSTهای مجازش auth/انتخاب فضای خودش و Quote غیرپرداختی هستند؛ کلاس، عضویت، grant، پیام، فایل، سفارش یا پرداخت واقعی ایجاد یا تغییر نمی‌دهد. صفحه‌ها با محافظ جلوگیری از نوشتن مرورگر و در تم روشن/تاریک و عرض۳۲۰/۳۹۰/۸۳۴/۱۴۴۰ بررسی می‌شوند. Mutationهای تجاری/نقش/آموزشیِ این تحویل در fixture محلی آزموده می‌شوند و تأیید DB/ACL واقعی نامیده نمی‌شوند.

## وضعیت بک‌اند و وابستگی‌های باقی

- گروه و کانال رسمی آموزشگاه نمونه هنوز Missing هستند؛ job/backfill سرور در اختیار کلاینت نیست و GET را به repair پنهان تبدیل نکرده‌ایم.
- lookup انتشار نمونه اکنون۴۰۴ با `ACADEMIC_ACTIVITY_PUBLICATION_MISSING` می‌دهد؛ کد قبلی `CONVERSATION_NOT_FOUND` دیگر مشاهدهٔ جاری همین نمونه نیست. نبود سابقهٔ انتشار، تحویل یا نتیجهٔ خالی موفق معرفی نمی‌شود.
- هر۴کلاس و۴عضویت نمونه نسخه داشتند؛ نام والد در۲رابطهٔ موجود از سرور خوانده شد. دعوت مستقل در نمونهٔ زنده خالی بود؛ هویت قبل از پذیرش با fixture بررسی شده است.
- Web Push در هرپنج حساب isConfigured=false بود. AI Runtime و retrieval طبق راهنمای انتشار فعال نیستند؛ هیچ AI/پرداخت/Push واقعی موفق فرض نشده است. کاتالوگ Individual حساب Personal نمونه خالی بود؛ gate Quote در واحد/مرورگر محلی بررسی شد.
- عرضهٔ سؤال‌به‌سؤال نتیجه/کلید، Support/Delete Account، PersonalClass pricing/payer و جزئیات مصوب آیندهٔ پیام‌رسان همچنان تصمیم یا قرارداد جدا می‌خواهند. نبود API ساخت/دعوت عضویت جدید از مسیر مدیر با «افزودن نقش به عضویت موجود» حل‌شده فرض نمی‌شود.
- صدور TLS، استقرار مقصد، تغییر secrets/volume یا اعمال job/migration انجام نشده است. Docker daemon موجود نبود؛ build برنامهٔ standalone و بررسی متصل محلی جای سلامت کانتینر سرور مقصد نیستند.

## بازتولید

از `web/`: `npm test`، `npm run typecheck`، `npm run lint`، `npm run generated:check`، `npm run format:check` و `NEXT_STANDALONE=true npm run build -- --webpack`. مرورگر: `PLAYWRIGHT_CHANNEL=chrome npx playwright test`. اجرای خواندن متصل، پس از `node scripts/integration-review.mjs`: `MAKAN_TEST_READ_SMOKE=1 node scripts/verify-vnext.mjs`. این ابزار عمداً به Test محدود است و ابزار تغییر دادهٔ واقعی نیست.

آزمون‌های راه‌اندازی بدون Docker میزبان: `MAKAN_DEPLOY_TEST_RUNNER=bwrap python3 -m unittest discover -s tests/deployment -p 'test_*.py'`. بستهٔ سورس قابل نصب با `python3 scripts/package-source.py` ساخته می‌شود؛ ZIP و SHA-256 در `output/delivery/` هستند. فایل `PACKAGE_CHECKS.json` بیرون ZIP، تطبیق محتوای بسته با سورس نهایی را ثبت می‌کند. برای استقرار مقصد، [راهنمای استقرار](deployment.md) و `setup.sh` ریشه همچنان مرجع‌اند.
