# رفع خطای ۴۰۴ گفتگوی آموزشگاه و حوالهٔ فنی بک‌اند

تاریخ بررسی: ۵ نوامبر ۲۰۲۶. سرور Test: `http://94.184.32.84:8090`. موضوع این سند فقط خطای ۴۰۴ گفتگوی سازمانی است که کاربر صریحاً انتخاب کرد. PDF تشخیص قبلی، سند تاریخیِ پیش از اصلاح FE-03 باقی می‌ماند.

## خطای واقعی و علت بازتولیدشده

گفتگوی نمونه در inbox سراسری همان حساب Teacher موجود است. در فضای Personal، API جزئیات و summary آن ۴۰۴ می‌دهند. پس از انتخاب نقش Teacher در فضای مجاز همان آموزشگاه، هر دو عملیات برای همان conversationId پاسخ ۲۰۰ دارند و participant همین کاربر Active است. این آزمایش نیاز به ساخت گفتگو، ارسال پیام، دعوت، تغییر عضویت یا تغییر privacy نداشت. فضای نشست QA در پایان برگردانده و خروج تأیید شد.

| عملیات | فضای Personal | فضای Organization معتبر |
|---|---|---|
| `GET /api/v1/conversations/{conversationId}` | 404 / CONVERSATION_NOT_FOUND | 200 / همان گفتگو، عضویت Active |
| `GET /api/v1/conversations/{conversationId}/summary` | 404 / CONVERSATION_NOT_FOUND | 200 / همان شناسه |

این رفتار، حذف گفتگو یا گم‌شدن عضویتِ این نمونه را اثبات نمی‌کند. علت رابط قبلی این بود که از inbox سراسری مستقیماً وارد چت می‌شد، در زمینهٔ نامنطبق جزئیات را می‌خواند و ۴۰۴ را عدم دسترسی دائمی فرض می‌کرد؛ سپس ردیف را پنهان می‌کرد. اصلاح FE-03 در کلاینت انجام شده است. قید دسترسی فعلی سرور دور زده نشده است.

زمان خواندن مستقیمِ تازه و hash نمونه در زیر است. UUID خصوصی، شماره، JWT و cookie در این سند نیستند. hash معادل ۱۲ نویسهٔ اول SHA-256 رشتهٔ conversationId است؛ شناسهٔ واقعی را از inbox حساب QA مجاز دریافت کنید.

```
checkedAtUtc: 2026-11-05T17:49:38.737Z
conversationHash: aee1cd4cbfb7
```

خطاهای واقعی برای جستجوی لاگ سرور:

```
Detail: HTTP 404
code: CONVERSATION_NOT_FOUND
Content-Type: application/problem+json
correlationId: 1492120aa1733221e8aa06d309617aa1
traceId: 00-1492120aa1733221e8aa06d309617aa1-f69a0fa90fb8a254-00

Summary: HTTP 404
code: CONVERSATION_NOT_FOUND
correlationId: 7f1da6794d8aa2d1657a5b2200cdc220
traceId: 00-7f1da6794d8aa2d1657a5b2200cdc220-b9b76c2d812edd3e-00
```

این پاسخ‌ها از سرویس واقعی دریافت شده‌اند. کد یا شناسهٔ پیگیری پیشنهادی به‌جای پاسخ واقعی جا زده نشده است. پاسخ فعلی code/trace/correlation دارد؛ نبود این فیلدها در این نمونه گزارش نمی‌شود.

## اصلاح انجام‌شده در فرانت‌اند

| بخش | رفتار جدید |
|---|---|
| ردیف سازمانی در inbox | پیش از جزئیات/تاریخچه، scope و organizationId معتبرِ summary با زمینهٔ نشست مقایسه می‌شوند. |
| زمینهٔ نامنطبق | کارت روشنِ «انتخاب فضای آموزشگاه برای این گفتگو» نمایش داده می‌شود؛ ردیف از inbox پنهان نمی‌شود. |
| انتخاب نقش | فقط فضای visible با canEnter=true و عضویت/نقش معتبر از snapshot خود حساب ارائه می‌شود؛ برای ردیف شناخته‌شده، فقط همان organizationId. |
| پس از انتخاب | انتخاب با endpoint موجود workspaces/select انجام و نشست/کش با معماری قبلی بازخوانی می‌شود؛ همان conversationId و فیلتر/جستجو حفظ می‌شوند. |
| لینک مستقیمِ ناشناخته | ۴۰۴ واقعی حفظ می‌شود. رابط فقط احتمال نیاز به زمینهٔ دیگر را توضیح می‌دهد؛ بدون دانستن summary ادعا نمی‌کند کاربر عضو این گفتگوست. |
| عدم مجوز یا شکست انتخاب | فضای غیرقابل ورود/آموزشگاه دیگر برای ردیف شناخته‌شده انتخاب نمی‌شود؛ شکست انتخاب، دسترسی یا موفقیت ساختگی ایجاد نمی‌کند. |
| گفتگوی شخصی | به فضای آموزشگاه وابسته نمی‌شود؛ نقش تحصیلی برای دسترسی به پیام شخصی جعل نمی‌شود. |

هیچ API یا نقش مدیریتی مالک به کلاینت اضافه نشد. نشانی مقصد از شناسهٔ encodeشده ساخته و مسیر بازگشت داخلی اعتبارسنجی می‌شود. نمایش canEnter یا نام نقش به‌تنهایی مجوز خواندن محتوا نیست؛ سرور دوباره عضویت و ACL منبع را بررسی می‌کند.

| انتخاب فضای همان آموزشگاه | انتخاب صریح و یک فرمان؛ بازگشت به همان چت و حفظ filter/q؛ داده فقط پس از زمینهٔ مجاز خوانده شود. |
| زمینهٔ از قبل صحیح | چت مستقیم باز شود؛ انتخاب دوباره لازم نباشد. |
| لینک مستقیم خارج صفحات بارگذاری‌شده | خطای اولیه حفظ و امکان انتخاب زمینهٔ مجاز ارائه شود؛ پس از انتخاب، همان شناسه بررسی شود. |
| canEnter=false یا آموزشگاه نامرتبط | دکمهٔ انتخاب نامعتبر و درخواست محتوای گفتگو وجود نداشته باشد. |
| کاربر غیرعضو با نقش معتبر | پس از انتخاب نقش هم سرور ۴۰۴ بدهد؛ هیچ متن یا مجوز گفتگوی دیگران نمایش داده نشود. |
| شکست workspaces/select | زمینهٔ قبلی و URL محفوظ؛ چت و تاریخچه پیش از موفقیت باز نشوند. |
| روشن/تاریک و چهار عرض | پیام، دکمه و ردیف بدون سرریز و در اندازهٔ قابل استفاده بمانند. |

### نتیجهٔ تازهٔ آزمون این تحویل

| بخش | نتیجهٔ ثبت‌شده |
|---|---|
| واحد | ۴۶۷ تست در ۶۶ فایل موفق؛ ۵ تست جدید برای مرز زمینه/assignment و مقصد امن. |
| مرورگر | گزارش اجرای سراسری: ۲۳۷ سناریو موفق؛ ۸ سناریوی جدید، صفر skip/retry خودکار. بازاجرای هر ۱۱ مورد دو فایل مرتبط نیز با خروج ۰ موفق شد. |
| بررسی واقعی | ۱۴ درخواست مستقیم و ۱۲ بررسی صریح BFF؛ ۸ تصویر زنده و ۸ تصویر fixture. زمینه‌ها بازگردانده و نشست‌ها خارج شدند؛ تاریخچه/نوشتن گفتگو مسدود بود. |
| کنترل کد | build تولیدی، typecheck، format و lint با ۳۵۵ ماژول بدون چرخه موفق؛ SDK قبلی ۲۸۹ عملیات و ۵۰۸ schema بدون مسیر مالک حفظ شد. |

فرایند اجرای سراسری پس از تولید گزارش کامل با ۲۳۷ موفق/صفر شکست و بدون خطای سطح گزارش، کد خروج ۱۴۳ داد؛ stderr خالی بود و علت پایان فرایند قطعی نشد. برای تأیید اجرای سالم، تمام ۱۱ سناریوی دو فایل مرتبط جدا با خروج ۰ موفق شدند. این ۱۴۳ وضعیت ابزار اجراست، نه کد خطای API پیام‌رسان؛ خروج سراسری ۰ فرض نشده است. شکست اولیهٔ locator آزمون و اصلاح آن نیز در JSON حفظ شده‌اند.

## پیشنهاد مشخص برای تیم بک‌اند

رفع رخداد رابط این نمونه به تغییر فوری authorization سرور نیاز ندارد؛ انتخاب درست زمینه اکنون در فرانت‌اند انجام می‌شود. بهبود زیر برای روشن‌شدن قرارداد و لینک مستقیم پیشنهاد می‌شود و هنوز در بک‌اند پیاده‌شده فرض نمی‌شود.

### BE-404-A - خلاصهٔ مجاز، مستقل از فضای انتخابی

راه پیشنهادی: همان endpoint موجود summary، برای گفتگویی که واقعاً در inbox مجاز همین حساب قرار دارد، metadata مجاز مانند scope و organizationId را مستقل از زمینهٔ انتخابی برگرداند. این API هم‌اکنون وجود دارد؛ endpoint تازه حدس زده نمی‌شود. message history، ارسال، فایل، مدیریت و Hub همچنان مجوز خود منبع و قید زمینهٔ معتبر را داشته باشند.

ابتدا وجود عضویت فعال واقعی حساب و سازمانِ همان گفتگو بررسی شود؛ صرف Teacher بودن یا داشتن یک آموزشگاه کافی نیست. کاربر نامرتبط، عضویت پایان‌یافته و شناسهٔ حدس‌زده‌شده همچنان ۴۰۴ بگیرند و metadata گفتگو افشا نشود. این پیشنهاد، summary جهانیِ مجاز را با inbox سراسری هماهنگ می‌کند و تشخیص خودکارِ آموزشگاه مقصدِ لینک مستقیم را برای کلاینت ممکن می‌سازد.

شبه‌کد پیشنهادی است؛ نام entity/handler با سورس واقعی بک‌اند تطبیق داده شود:

```
summary = findSummaryVisibleInAccountInbox(actorId, conversationId)
if summary is null:
    return NotFound(CONVERSATION_NOT_FOUND)

if not activeResourceMembership(actorId, conversationId):
    return NotFound(CONVERSATION_NOT_FOUND)
return Ok(safeSummary(summary))

// Full content keeps its own context and resource authorization:
authorizeSelectedOrganizationAndResource(actorId, conversationId)
```

NotFound در این شبه‌کد باید از سازندهٔ ProblemDetails موجود با code/traceId/correlationId واقعی استفاده کند؛ به پاسخ string یا ۴۰۴ خالی تبدیل نشود.

### BE-404-B - اگر تغییر summary فعلاً ممکن نیست

پس از اثبات مجوز حساب برای وجود همان گفتگو، تعارض زمینه با خطای ماشین‌خوان جدا اعلام شود. پیشنهاد قرارداد، نه پاسخ فعلی سرور:

```
HTTP 409
code: CONVERSATION_WORKSPACE_REQUIRED
requiredAction: SELECT_WORKSPACE
requiredWorkspaceType: Organization
requiredOrganizationId: authorizedConversation.OrganizationId
traceId: request.TraceId
correlationId: request.CorrelationId
```

اطلاعات زمینه فقط پس از تأیید مجوز همان منبع افشا شوند؛ برای شناسهٔ نامرتبط ۴۰۴ حفظ شود. گزینهٔ A با DTO فعلی سازگارتر است. برای گزینهٔ B، schema/status/code و نمونه را در OpenAPI منتشر و generator و مصرف code کلاینت را هم‌زمان به‌روز کنید. این کد هنوز پیاده نشده است؛ متن انسانی detail مبنای تشخیص نباشد.

## اگر در فضای صحیح هم ۴۰۴ باقی ماند

در این نمونه پس از انتخاب صحیح، هر دو خواندن ۲۰۰ شدند؛ بنابراین ایراد DB یا ACL پس از انتخاب اثبات نشده است. اگر حساب دیگری هنوز در فضای صحیح ۴۰۴ گرفت، تیم بک‌اند این موارد را با همان correlationId بررسی کند:

- actor و session درخواست با حساب موردنظر یکی باشند؛ نقش انتخابی از membership فعال همان حساب و organizationId همان گفتگو آمده باشد.
- conversation.organizationId، زمینهٔ انتخابی و membership سازمانی دقیقاً برابر باشند؛ عنوان آموزشگاه یا نام نقش مبنای join/اجازه نباشد.
- وضعیت participant، عضویت و role assignment و سازمان فعال باشند؛ endpointهای summary/detail/history/file/Hub از همان قواعد معتبر استفاده کنند.
- خواندن inbox از ردیف منقضی یا کشِ قبل از revoke استفاده نکند؛ اگر گفتگو مجاز نیست، اطلاعات خصوصی در summary یا رویداد نشت نکند.
- برای فضای رسمی، binding واقعی کلاس/آموزشگاه و وضعیت provisioning مستقل بررسی شوند؛ Missing رسمی با گروه شخصی یا تعارض زمینه یکی نیست.
- انتخاب workspace و تولید/گردش توکن یا claims به‌صورت سازگار انجام شود؛ درخواست‌های زمینهٔ قبلی قابل استفاده در زمینهٔ تازه نباشند.

از حذف شرط سازمان، افزودن participant ساختگی، دست‌کاری نقش/DOB، غیرفعال‌کردن ACL یا بازگرداندن ۲۰۰ خالی برای پنهان‌کردن خطا استفاده نشود. SQL، نام جدول یا مسیر فایلِ بک‌اند در این سند حدس زده نشده است؛ سورس بک‌اند و DB در این workspace نیستند.

### متن آمادهٔ ارسال به تیم بک‌اند

در Test، گفتگوی Organization موجود در inbox حساب Teacher از زمینهٔ Personal برای detail و summary خطای ۴۰۴ با code=CONVERSATION_NOT_FOUND دارد؛ پس از انتخاب فضای مجاز همان آموزشگاه، همان دو عملیات ۲۰۰ و participant فعال‌اند. خطای انتخاب زمینه و حذف ردیف در فرانت‌اند اصلاح شده است. لطفاً قرارداد summary مجاز را با inbox سراسری هماهنگ کنید یا فقط برای منابعی که عضویت حساب در آن‌ها اثبات شده، خطای تعارض زمینهٔ مستقل و مستند بدهید. برای سایر کاربران/شناسه‌ها ۴۰۴ و ACL حفظ شود. دو correlationId واقعی در صفحهٔ اول برای بررسی لاگ آمده‌اند. اگر پس از انتخاب صحیح هم ۴۰۴ رخ داد، actor/membership/role/organization/participant و consistency کش/claims مطابق چک‌لیست بررسی شوند.

شواهد و نتیجهٔ آزمون‌ها در `web/docs/quality/MESSAGING_404_20261105_*.json` هستند. ساخت و پذیرش/رد دعوت، privacy و پیام‌های دیگران در این نوبت تغییر نکردند. نوشتن زنده محدود به احراز هویت و انتخاب/بازگرداندن فضای نشست QA بود؛ خواندن پیام و عملیات تغییردهندهٔ گفتگو در بررسی متصل مسدود ماندند.
